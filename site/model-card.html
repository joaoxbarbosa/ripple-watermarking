Ripple Fingerprint

A secret-key watermark and source-attribution system for text from language models, built for the Ripple family. It replaces the last sampling step of a model and comes with an exact statistical detector.

02How it works
1 · Keyed randomness

HMAC-SHA256(key, last 3 token ids) seeds a SHAKE-256 stream with one uniform u per vocabulary token.

2 · Exact sampling

The token is argmax u1/p. It is drawn with probability exactly p, but tokens with a high u win more often.

3 · Exact test

The detector sums −log(1−u). For text the key didn't write the sum is Gamma(n, 1), so the p-value is exact.

4 · Local, so edit-robust

Each seed depends only on a 3-token window. An edit spoils the windows that touch it, and the rest still score.

  • Repeated-context masking. A 3-token context that already appeared in the response is sampled with true randomness, and the detector skips it.
  • Entropy gate. True randomness is used until the response has 8 bits of surprisal, so the same prompt still gives different answers.
  • Attribution. Each model's key is HMAC(master, label). The whole text and its best spans are tested per model, corrected for every model and every possible segment, so the chance of naming any model for text it didn't write stays below the threshold.

04Intended use

Use it for

  • Marking text from your own deployed models so you can later check whether a text came from them, and from which one.
  • Splitting a mixed document into the stretches each of your models wrote.
  • Detection run as a service that holds the key.

Not for

  • Detecting text from models that don't sample with these keys.
  • Proving a human wrote something. A negative result only means this key's watermark isn't there.
  • Greedy decoding (T = 0) or beam search, which have no sampling randomness.
  • Shipping the key to clients.
05Evaluation

Detection by threshold

Robustness to word edits (p < 10⁻⁵, 3 random edits per reply)

Calibration and attribution

    Earlier results (GPT-2)

    200-token GPT-2 generations at T = 0.8, top-p 0.95 were 100% detected, clean and with up to 30% of words replaced (median p 7×10⁻¹³ at 30%). Mean NLL of watermarked text was 4.02 ± 0.11 against 4.19 ± 0.10 for plain sampling, within noise. GPT-2 has more randomness per token than a tuned chat model, so it is detected more easily.

    Not yet measured

    • Ripple-65B itself. Run RIPPLE_FP_TEST_MODEL=/path/to/ripple pytest tests/test_hf.py on a machine that can load it.
    • Paraphrasing and translation attacks, beyond random word edits.
    • Larger prompt sets and other domains such as code.

    06Limitations and risks
    • Rewrites remove it. A full paraphrase or translation keeps the meaning but changes the tokens.
    • Low-entropy text carries little signal. Code, lists, one-line facts and near-deterministic chat replies need more tokens, and some 300-token replies are never detected at p < 10⁻⁵.
    • The key is the whole secret. Anyone with it can detect, forge or strip the watermark.
    • Retokenization. Detection re-encodes the text, so whitespace or Unicode normalization can spoil the tokens it touches.
    • Many responses. Common 3-token contexts recur across responses and reuse the same keyed draws. No single response changes, but a large set could in principle show structure. A larger context_width reduces this, at some cost in edit robustness.
    • Only your models. A negative result is not evidence that a human wrote the text.
    07Usage
    from ripple_fingerprint import Watermarker
wm = Watermarker(key=SECRET_KEY)
state = wm.new_state()                            # one per response
tok = wm.sample(probs, history_token_ids, state)  # replaces the multinomial draw
wm.detect(token_ids).p_value
    from ripple_fingerprint import ModelRegistry
reg = ModelRegistry(master_key=MASTER_SECRET)
wm_big = reg.register("ripple-65b", tokenizer_big)
reg.attribute(text).best    # "ripple-65b", or None
