# Model card: Ripple Fingerprint

A secret-key watermark and source-attribution system for text generated by
language models, built for the Ripple model family. It isn't a language model
itself. It replaces the final sampling step of one, and comes with a detector.

The web version of this card is `site/model-card.html`. Its numbers come from
the latest `site/results.js`, and it links to the full results page
(`site/index.html`).

## Details

| | |
|---|---|
| Package | `ripple-fingerprint` 0.1.0 (`ripple_fingerprint/`) |
| Type | Sampling-time watermark (keyed Gumbel-max / exponential race) with an exact statistical detector |
| Built for | `ricursiveAI/Ripple-65B-Preview`; works with any model that exposes next-token probabilities |
| Back ends | Pure NumPy core; Hugging Face `generate` / `LogitsProcessor`; Apple MLX (`mlx-lm`) |
| Dependencies | `numpy`, `scipy` (core); `torch`, `transformers` (HF); `mlx-lm` (MLX) |
| Secret | One key of at least 16 bytes, or one master key for a registry of models |
| License | No license file in the repository yet |

## How it works

1. At each step the model gives a next-token distribution `p`, after
   temperature, top-k and top-p.
2. `HMAC-SHA256(key, "ripple-fingerprint/v1" || last 3 token ids)` seeds a
   SHAKE-256 stream with one uniform `u_v` per vocabulary entry.
3. The chosen token is `argmax_v u_v^(1/p_v)`. When the `u_v` are uniform
   this picks `v` with probability exactly `p_v`, so each token is still an
   exact sample from the model. Tokens with a high `u` win more often.
4. The detector recomputes `u` for each token and sums `-log(1 - u)`. For text
   the key didn't write, each term is Exp(1) and the sum is Gamma(n, 1), so
   the p-value is exact.

Two rules keep the output distribution exact across a whole response:

- **Repeated-context masking.** A 3-token context that already appeared in
  the response is sampled with true randomness, and the detector skips it.
- **Entropy gate.** True randomness is used until the response has collected
  8 bits of surprisal, so the same prompt still gives different answers.

**Attribution.** `ModelRegistry` gives each model the key
`HMAC(master, "ripple-fingerprint/model-key/v1" || label)`. Each model gets
two tests, the whole text and the best-scoring spans. Both are
Bonferroni-corrected across all models and, for spans, across every possible
segment. The chance that any model is named for text it didn't write stays
below `fpr`.

## Parameters

| Parameter | Default | Effect |
|---|---|---|
| `context_width` | 3 | Tokens hashed into each seed. Smaller is more robust to edits; larger repeats contexts less often across responses |
| `entropy_threshold` | 8.0 bits | Surprisal sampled with true randomness at the start of each response |
| `fpr` | 1e-5 | Detection threshold, and the exact false-positive rate per test |
| key length | ≥ 16 bytes | Enforced by the constructor |

## Intended use

- Marking text from your own deployed models so that you can later check
  whether a given text came from them, and from which one.
- Splitting a mixed document into the stretches written by each of your
  models.
- Running detection as a service that holds the key.

## Out of scope

- Detecting text from models that don't sample with these keys. It can't say
  whether some other AI wrote a text.
- Proving that a human wrote something. A negative result only means that
  this key's watermark isn't there.
- Settings without sampling randomness: greedy decoding (T = 0) or beam
  search.
- Publishing the key. Anyone who holds it can detect, forge or strip the
  watermark.

## Evaluation

### Setup

| | |
|---|---|
| Model | Qwen3-VL-4B-Instruct (MLX, 8-bit) on an Apple M4 Pro |
| Prompts | 16 open-ended chat prompts (stories, explanations, advice, poems) |
| Replies | One fingerprinted and one plain reply per prompt |
| Sampling | T = 1.0, top-p = 1.0, up to 300 new tokens, chat template, no thinking |
| Threshold | p < 1e-5 unless noted |
| Scripts | `docs/run_experiment.py`, then `docs/make_stats.py` |

Sampling is random, so a rerun gives somewhat different counts. The figures
below are from the run shipped in `site/results.js`, generated 2026-11-13.

### Detection

| Threshold | Fingerprinted detected | Plain flagged |
|---|---|---|
| p < 0.01 | 15 / 16 | 0 / 16 |
| p < 1e-3 | 15 / 16 | 0 / 16 |
| **p < 1e-5 (default)** | **12 / 16** | **0 / 16** |
| p < 1e-8 | 10 / 16 | 0 / 16 |

- Median p-value of a fingerprinted reply: about 1e-10. The smallest p-value
  for a plain reply was 0.03.
- Detected replies crossed p < 1e-5 after a median of 120 tokens.
- The replies that went undetected were ones where the model was close to
  deterministic, so there was little randomness to carry the signal.

### Robustness to edits

Full replies with random words replaced by filler words, or deleted, three
random edits per reply, re-tokenized, p < 1e-5:

| Words changed | 0% | 10% | 20% | 30% | 40% | 50% |
|---|---|---|---|---|---|---|
| Replaced | 75% | 63% | 46% | 33% | 6% | 2% |
| Deleted | 75% | 54% | 40% | 31% | 8% | 6% |

No plain reply was flagged after any edit.

### False-positive calibration

1,920 tests of text a key didn't write (32 replies × 60 unrelated keys). The
p-values are uniform: none fell below 1e-5, the smallest was 5.3e-4, and 0.8%
fell below 0.01 against 1% expected.

### Attribution

Five models registered on one tokenizer; only model A sampled the replies.

- 11 of 16 fingerprinted replies were attributed to model A and only model A.
  The registry corrects for testing five models, so it needs a little more
  evidence than a single-key check.
- No reply was ever attributed to one of the four other models.
- No plain reply was attributed to any model.
- Mixed documents (plain + fingerprinted + plain reply): the fingerprinted
  span was found in 4 of 8, overlapping the true passage by 75–100%. No
  span was assigned to a wrong model.

### Speed

Tokens per second relative to MLX's own sampling loop, Qwen3-VL-4B-Instruct
8-bit on an Apple M4 Pro (`docs/speed.json`):

| Configuration | Share of native speed |
|---|---|
| Fingerprinted | 97% |
| Fingerprinted + visualizer trace | 94% |
| Fingerprinted, top-p 0.95 | 92% |

### Earlier results (GPT-2)

200-token GPT-2 generations at T = 0.8, top-p = 0.95: 100% detected clean
and with up to 30% of words replaced (median p 7e-13 at 30%). Mean NLL of
watermarked text was 4.02 ± 0.11 against 4.19 ± 0.10 for plain sampling, a
difference within noise. GPT-2 has more randomness per token than a tuned
chat model, which is why it is detected more easily than Qwen3-VL-4B above.

### Not yet measured

- Ripple-65B itself. Run `RIPPLE_FP_TEST_MODEL=/path/to/ripple pytest tests/test_hf.py`
  on a machine that can load it.
- Paraphrasing and translation attacks, beyond random word edits.
- Larger prompt sets and other domains such as code.

## Limitations and risks

- **Rewrites remove it.** A full paraphrase or translation keeps the meaning
  but changes the tokens. The signal fades as untouched 4-token runs
  disappear.
- **Low-entropy text carries little signal.** Code, lists, factual one-liners
  and near-deterministic chat replies need more tokens, and some 300-token
  replies are never detected at p < 1e-5.
- **The key is the whole secret.** Anyone with it can detect, forge (make
  text look like your model's) or strip the watermark.
- **Retokenization.** Detection re-encodes the text. Whitespace or Unicode
  normalization changes can spoil the tokens they touch.
- **Repeated prompts.** Across many responses, the same 3-token contexts
  recur and reuse the same keyed draws. This doesn't change any single
  response's distribution, but a large set of responses could in principle
  reveal statistical structure. A larger `context_width` reduces this, at a
  cost in edit robustness.
- **Only your models.** A negative result is not evidence that a human wrote
  the text.

## Usage

```python
from ripple_fingerprint import Watermarker
wm = Watermarker(key=SECRET_KEY)
state = wm.new_state()                            # one per response
tok = wm.sample(probs, history_token_ids, state)  # replaces the multinomial draw
wm.detect(token_ids).p_value
```

```python
from ripple_fingerprint import ModelRegistry
reg = ModelRegistry(master_key=MASTER_SECRET)
wm_big = reg.register("ripple-65b", tokenizer_big)
reg.attribute(text).best    # "ripple-65b", or None
```
